# 2026-11-03 真机验收

## 环境与安装

- Xiaomi 17 Pro Max（型号 2509FPN0BC），Android 17 / API 37，HyperOS OS4.0。
- 原 App `3.2.3+31` → 正式签名预览 `3.2.4-alpha.1+32`，USB 覆盖安装成功，未清除数据；最近会话、原皮肤与图标保留。APK 证书与 3.2.3 一致。
- 只使用独立 DSH_HOME 下的 DSH Web `0.2.1-rc.5`，插件 `3.2.4-alpha.1`，通过 USB reverse 连接；原桌面实例不重启、不升级。
- 在独立会话调用 loopback 合成审批端点，走真实宿主审批 / SSE / App 通知链路；没有给真实模型派任务。打包插件必须按实际安装方式解析宿主 peerDependencies，不能用开发测试依赖的副本代替宿主身份模块。

## 已通过

| 场景 | 实测结果 |
|---|---|
| 前台停在设置页 | 一次审批只有一条 `dsh_attention` 业务通知，无应用内重复横幅 |
| 点击系统通知 | 进入正确会话，显示审批卡 |
| 手机允许一次 | 宿主返回 `allowed-once`，业务通知撤销，宠物常驻通知保持 |
| 正看该会话时来审批 | 仅显示会话卡片，系统通知和横幅均不额外弹出 |
| HOME 后来审批 | 后台收到系统业务通知；无第二条业务通知 |
| 待办未结算，App 进程重启 | 回放前后仍一条通知，稳定 notification ID 完全相同 |
| App 进程结束后宿主结算 | 系统旧通知保留；重新启动后由宿主待办快照精确撤销 |
| 常驻模式 | KeepAliveService 进入前台，specialUse、ID 3515；原生 / Dart 心跳持续约 3 分钟，期间后台审批可提醒和撤销 |
| 常驻 / 宠物切换 | 切回宠物后 KeepAliveService 销毁，只保留宠物服务，常驻通知不互相覆盖 |
| 宠物未读数 | 宿主未读 7，宠物角标 7；超过 60 秒不自行清零；宿主标已读为 0 后角标消失 |
| 更新入口 | 正确显示 App `3.2.4-alpha.1+32` 和插件 `3.2.4-alpha.1`；当前发行版缺少清单时显示明确文案，未误进入安装流程 |

Android 可能为常驻通知与业务通知生成 ID 0 的系统分组摘要；它不计为第二条审批业务通知，核对时按 `dsh_attention` 的业务 ID 判断。

## 限制与剩余验收

- 本次后台持续性是约 3 分钟、USB 连接状态的实测，不能推断息屏 30 分钟、Doze、拔线后 ROM 管理、系统强制停止等场景。
- 通过 adb 覆盖安装验证了正式签名兼容性；App 内“下载配对包 → 未知来源授权 → Android 系统安装器确认”仍需有下一版有效签名清单 / 配对包后验证，未把 adb 安装等同于该完整流程。
- 宠物动画仍可显示；长按面板的自动化触摸未稳定命中，不记为面板交互通过。源代码保留面板不代替业务已读的逻辑，本轮角标同步已实测。
- 未改系统省电白名单或通知渠道权限；权限拒绝 / 渠道静音的降级矩阵由组件测试保护，仍可作为额外真机项目。

## 清理与恢复

验收使用的临时输入法仅用于避免原输入法改写 URL 标点，测试结束恢复原讯飞输入法并卸载测试包。恢复原电脑地址 / 口令 / 候选地址列表、桌面宠物开启、常驻提醒关闭和原贴边躲藏设置；移除 USB reverse，关闭独立 Web 实例。原局域网地址在本次验收前已不可达，恢复原配置后不把这个网络问题记成新版本回归。
