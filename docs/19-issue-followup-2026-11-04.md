## #68 下载期间的后台服务

在既有私有断点、Range / If-Range 和完整长度校验上，新增 DownloadService，使用 Android `dataSync` 前台服务类型。只在前台用户明确发起下载时启动；通知显示本地进度与暂停，不包含远端路径、地址或口令。通知渠道和 ID 与宠物、提醒保活独立，下载不改这两项设置。

网络和断点仍由 Dart 管理，没有第二套下载账本。原生通知暂停、系统停止或 Android 15+ 的 `onTimeout` 回调会取消对应传输，保留真实已写入的字节；成功、失败和暂停后停止服务。超时回调即使遇到已解绑的 Flutter 引擎，也会停止服务。不会靠自动重启服务绕过累计时限。旧任务的迟到进度/停止回调不能影响新任务。

启动后确认实际运行状态；通知关闭、后台启动限制或原生启动失败时，界面明确退回前台下载。另一项传输仍活动时拒绝再启动，不伪装成功。减少通知更新频率，避免每个网络 chunk 都走平台通道。

另修复恢复列表的 Windows 路径判断：目录枚举返回的反斜杠路径与构造路径不一致时，以绝对文件 URI 比较，避免已经持久化的断点不出现在列表。

专用服务提高后台存活能力，不绕过 Doze、强制停止或厂商冻结。之前的 USB 报告验证的是旧版续传与完整性，不能当作本次新服务的真机证明。本轮补测时 ADB 显示 0 台设备，已请维护者重新连接；新的锁屏传输、通知暂停与系统超时现场验证尚未执行，因此 #68 保持开放。

文件权限继续采用 [安全文档](04-security.md) 记录的完整宿主信任模型。仅过滤工作区会被同一身份的 cwd 注册入口绕过；本轮不修改任意新目录建会话功能，也不把界面导航边界称为授权隔离。真正受限身份需连同宿主批准根目录和注册授权一并设计。
