# 01 产品需求文档（PRD）— dsh-mobile-remote

> 版本：v2.4.0 · 状态：全部功能已实现（v0.1/v1 历史部分保留作演进记录） · 适用范围：本插件全部迭代

## 1. 产品定位与目标用户
- **产品定位**：DeepSeek Harness 的手机远程操作插件 + 原生 App。当电脑端 dsh web 在线运行时，使用者可以离开电脑，通过手机 App（DSH Remote）向运行中的 agent 发消息、派任务、查看进度、接收完成通知、审批决策、管理历史会话，并跳转 DeepSeek 开放平台充值。
- **目标用户**：本人（单人使用）。设计上不假设多用户、不做账号体系。
- **一句话**：把"dsh web 桌面会话"延伸到口袋里——电脑是执行者，手机是遥控器。

## 3. 业务主流程与分支流程

### 3.1 主流程：手机发消息
```
手机打开 /m（扫码/手动输入地址）→ bootstrap 获取状态（agent 是否在线、是否需口令）→ [分支 A] 口令已启用且未认证 → 登录（输入口令）→ Set-Cookie
  → 输入消息 → POST /api/send { sessionId?, text }
  → agent.followup() 注入 → agent 唤醒执行
  → 移动页 SSE（/api/events）实时收到 session/event（turn/start → assistant/chunk 流式 → tool/result → turn/end）
  → agent 空闲 → 浏览器通知"任务完成"
```

### 3.2 分支流程

- **A. 认证**：口令为空（默认）→ 跳过；口令非空 → 未认证请求一律 401，页面显示登录表单。
- **B. 无运行中 agent**：`/api/send` 返回 503，页面提示当前没有运行中的 agent（电脑端未打开会话）。
- **C. 多会话**：存在多个 agent 时，页面顶部会话选择器指定目标；未指定默认第一个 root agent。
- **D. 断线重连**：SSE 断开 → 页面自动重连（指数退避），重连后拉取历史增量补齐。
- **E. 通知不可用**：浏览器未授权通知 → 页面内横幅提示，消息流仍正常显示。
## 4. 页面原型（文字线框）

```
┌──────────────────────────────┐
│ ◀ agent 状态｜会话: <当前> ▸ │
│ → 顶部栏：状态点(running/idle)、会话切换 │
├──────────────────────────────┤
│ [Tab1 对话] [Tab2 会话] [Tab3 更多] │
├──────────────────────────────┤
│ 对话 Tab（消息流）           │
│   · 消息流（user 右气泡 /    │
│     assistant 左气泡 / 工具行 / │
│     轮次分隔线）             │
│   · 底部输入条：文本框 发送  │
├──────────────────────────────┤
│ 会话 Tab（会话列表）         │
│   · 会话列表：id、创建时间。 │
│     状态（运行/空闲）        │
│   · 点击切换当前会话         │
├──────────────────────────────┤
│ 更多 Tab（更多）             │
│   · 访问地址列表 + 二维码    │
│   · 充值入口卡片             │
│   · 安全状态（口令开关）     │
│   · 刷新/关于                │
└──────────────────────────────┘
```

- 适配规则：手机优先（375px 起），桌面浏览器可用（内容居中限宽 480px）；跟随系统深浅色（`prefers-color-scheme`）。
- 触控目标 ≥ 44px；输入条固定底部（键盘弹起时 iOS 安全区适配 `env(safe-area-inset-bottom)`）。
## 5. 非功能需求
| 类别 | 指标 |
|---|---|
| 响应时间 | API 请求（bootstrap/send/历史）≤ 200ms（本机回环）；SSE 事件延迟 ≤ 500ms |
| 可用性 | 电脑端 dsh web 在线即可用；GUI 重启后移动页自动恢复（会话持久化在 dsh 侧） |
| 并发 | 单用户；SSE 连接数上限 16（超出拒绝并提示） |
| 兼容性 | 手机：iOS Safari ≥ 15、Android Chrome ≥ 90（现代浏览器，含 Notification/EventSource）；桌面：Chrome/Edge/Firefox |
| 流量 | 事件摘要截断：tool/result 内容 ≤ 2000 字符下发给移动端，assistant 文本 ≤ 20000 字符 |
| 安全基线 | 见 04-security.md：威胁模型、口令方案、传输安全要求 |
| 可维护性 | 零构建（无前端打包步骤）；插件为纯 ESM；配置项集中在 Config schema |

## 6. 数据与埋点
- 不采集任何埋点；不新增持久化存储（口令仅存于 dsh profile 配置；会话数据由 dsh 现有 session 服务持有）。
## 7. 迭代优先级
| 迭代 | 范围 | 目标 |
|---|---|---|
| v0.1（本次） | F1 F2 F3 F8 F9 + 页面骨架 | 打通「手机发消息 → 看进度 → 收通知」主链路 |
| v0.2 | F4 会话历史、F6 充值入口、F7 二维码 | 会话管理 + 常用入口 |
| v0.3 | F5 回答/审批独立端点、通知增强 | 移动端全场景操作 |

## 8. 验收标准（v0.1）
1. 手机与电脑同一网络（或 Tailscale 组网）时，浏览器打开 `/m` 可见页面与 agent 状态正确。
2. 发送消息后，电脑端 GUI 会话出现该消息，agent 开始执行，移动页实时看到流式回复。
3. agent 完成任务空闲时，手机浏览器收到通知（页面后台时）。
4. 启用访问口令后，未认证访问全部移动 API 返回 401；登录后正常。
5. 无运行中 agent 时发送消息，页面给出明确提示而非静默失败。

# 第二部分：移动端产品版（v2.0，与 00-开发总纲配套）
## 9. 界面定稿（冻结）

视觉与信息架构以 `prototype/app-prototype.html`（v7）为准，要点：
- **视觉**：DeepSeek 品牌配色（主色 `#426EFE`，深色 `#0E1116`/`#161B22`）、衬线大标题（Georgia/宋体）、1.5 线宽 Lucide 风格线性图标、大圆角（16-24px）、默认跟随系统深浅色
- **信息架构**：侧边栏三项——首页 / 会话 / 设置；对话、通知为详情页；无底部 tab
- **首页固定欢迎界面**：衬线欢迎语 + 最近会话 + 新建会话 + 底部输入条（不做状态切换）
- **新建会话当场选模式**（标准 PTC/极简/创造），预选值来自设置默认
- **对话页**：输入条两行式（第一行模型/权限胶囊，第二行 + 输入/发送）、动作区（可选，空则隐藏）、工具折叠、微信式无限上翻（滑到顶自动加载更早 + 回到底部浮钮）、问询/审批弹窗卡片（与 PC 端同一 pending）
- **通知中心**：三类通知（完成/需要回答/失败）、未读徽标、全部已读、点击直达会话
- **设置页**：连接、默认权限预设、默认 Agent 预设、通知开关、显示开关、关于
- **诚实原则**：未实现功能明确标注"开发中"

## 11. 验收标准（v2.0，Phase 1 完成标志）
1. 手机完成「新建会话（选模式）→ 发消息 → 流式回复 → 通知 → 审批 → 翻历史记录」全链路。
2. 模型/推理强度/权限预设选择与 PC 端一致，Full Access 有风险确认。
3. 通知中心三类事件正确聚合，未读状态跨重启保留。
4. 既有 v0.1 端点全部保持兼容（回归）。
5. 问询/审批弹窗与 PC 端同一 pending：任一端回答，两端同步消失（v2.3+，用例见 05-test-cases F-15/F-16）。
