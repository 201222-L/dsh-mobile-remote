# 后台提醒与桌面宠物

## 后台运行的真实边界

浏览器页面隐藏后可能被节流、冻结或回收；这会影响页面接收 / 呈现事件，不会因为本插件的 SSE 断开就取消已交给宿主的任务。任务仍可能停在审批、问询或真实错误上。完成、失败、需要回答的提醒应由宿主推送桥独立投递，不能依赖页面常驻。

Android 的常驻服务提升存活概率，不能承诺强制停止、系统清理、ROM 冻结后仍在线。服务与 Dart 心跳用于区分“服务在、Dart 停了”；省电设置入口和通知权限提示仍保留。已开启常驻服务的手机也建议配置宿主推送兜底。

设置里的测试推送使用现有 `/push-test`，环境诊断显示各通道最近投递结果。现场排查按宿主任务事件 → 当前待办 → 推送结果 → 手机服务 / Dart 心跳顺序核对；不要把页面失去刷新直接归因成任务停止。

## 通知职责

- 宿主维护任务状态、审批 / 问询和通知中心的未读事实。
- App 的结构化事件、判据与持久账本是系统业务通知的单一入口；已移除旧 rpcId 通知回调链。
- 桌面宠物悬浮层保留动画、任务状态、拖动、互动和面板，只呈现宿主通知中心的未读快照；它不发系统业务通知、不自行决定业务已读、去重或撤销。

`FloatingBubbleService`、`Floating`、`dsh/floating` 等内部名称暂时保留用于兼容已有服务 / 偏好；当前产品是桌面宠物，不再是旧版圆形悬浮球。

文件下载的 `DownloadService` 使用独立 `dsh_downloads` 通知渠道、通知 ID 和 `dataSync` 类型，仅显示用户发起传输的进度与暂停入口；它不接收 SSE、不参与审批或任务通知判定，不改变桌面宠物与提醒保活的互斥设置。Android 15+ 系统超时会停止服务并保留断点；该服务不承诺绕过 Doze 或厂商冻结。

## 提醒矩阵

| 状态 | 系统通知 | 应用内横幅 |
|---|---|---|
| 正在看该会话 | 不弹，使用会话卡片 | 不弹 |
| 前台其它页面，权限 / 渠道可用 | 弹 | 不重复弹 |
| 前台其它页面，权限 / 渠道不可用 | 不弹 | 兜底 |
| 后台，权限 / 渠道可用 | 弹 | 不弹 |
| 后台，权限 / 渠道不可用 | 不弹；依赖独立推送兜底 | 不弹 |

审批身份优先使用 approvalId，问询使用 rpcId；账本加认证宿主作用域，避免不同电脑的身份冲突。账本只存最小 key / id / 状态，先恢复再串行消费事件并持久化。当前 Android 通知渠道状态会实际读取。

重连时宿主在 pending 帧回放后，同一 SSE 流追加 `attention/snapshot {version:1,pending:[{kind,sessionId,identity}]}`。这是完整快照边界：App 只撤销该宿主已不在待办中的业务通知，不影响其它电脑或保活 / 宠物常驻通知。旧宿主没有快照时保留既有行为，不凭超时猜测待办已结束。

桌面宠物角标使用 App 推送或宠物自行读取的同一宿主通知中心快照；打开面板不会把未读伪装成已读，60 秒也不会自动清零。宠物仍可在 App 的 Dart 侧暂停时读取宿主状态并展示，SSE 事件只驱动动画和触发快照刷新。

## 宠物资源（issue #58）

首页与原生桌面宠物共用 `dsh-mobile-app/assets/pet/`，动画清单和 MIT 授权也放在 Flutter assets 中。原生服务通过 Android 的 `ApplicationInfoLoader` 读取 bundle 路径，不需要启动 Dart 引擎，适用于服务独立恢复。首页四个互动动画与静态图保留原文件；其它动作迁入同一目录，相同内容的 waiting / working_search 共用一个文件。清单帧数和帧时长按实际 WebP 更新。

旧两份资源合计 8,716,539 字节，现为 6,509,569 字节（约减少 25.3%，不含清单和授权）。构建脚本默认输出这一处并按内容去重。APK 总体积需以新构建实测，资源数据不代表真机渲染或后台通知验收。

## 验收

先记录 source commit、实际运行的插件版本和手机 build。覆盖一条审批只弹一次、重连回放不重复、桌面先答后手机重启不留旧通知、不同宿主相同 identity 不错撤、权限拒绝 / 渠道静音、App 后台 / 被清理、桌面宠物与常驻模式切换、宠物未读减少、通知点击导航。没有连接真机时不能把组件测试或其它人的报告记成本机真机通过。
