# 08 扩展与二次开发指南
> 本项目的设计目标之一就是**容易扩展**：从改一行文案到加一个完整功能，都有清晰的切入点。
> 欢迎你在此基础上创建自己的版本，也欢迎把好的改动 PR 回上游。
> 注：v2.1 起已移除网页版（`page.html`），移动端仅原生 App；扩展主要落在服务端端点、插件契约与 App 界面。
## 1. 扩展点总览（由浅入深）

| 层级 | 能改什么 | 难度 | 入口 |
|---|---|---|---|
| 文案/样式 | 首页文案、配色、圆角、间距 | ★ | App `lib/theme.dart`、各 screen |
| 插件动作区 | 第三方插件往移动端加"快捷动作" | ★★ | 插件契约 `mobileActions`（见 §2） |
| 推送通道 | 自定义通知渠道 | ★★ | `pushUrls` + `pushToChannel`（见 §3） |
| 服务端端点 | 新 API（自定义数据/操作） | ★★★ | `lib/index.js` `handleApi` |
| App 原生界面 | 主题、图标、页面、深色模式 | ★★★ | `dsh-mobile-app/`（Flutter） |
| 桌面设置页 | 扫码页样式/信息 | ★★ | `lib/client.js`（dsh 客户端模块） |

## 2. 插件动作区（最推荐的扩展方式）

任何 dsh 插件都可以向移动端注册"快捷动作"——对话页底部自动出现动作按钮，点击后带参数执行。`mobileActions` 服务由本插件提供（`ctx.provide`），**其他插件消费**：

```js
// 你的插件里：取服务并注册
const mobileActions = ctx.get("mobileActions");
mobileActions?.register({
  id: "translate-clipboard",
  title: "翻译剪贴板",
  icon: "globe", // 移动端 App 内置图标 id（见 dsh-mobile-app 图标映射）
  fields: [{ key: "target", label: "目标语言", placeholder: "en" }],
  handler(args) {
    const text = clipboard.read();
    return translator.translate(text, args.target);
  },
});
```

注册后：移动端对话页自动出现「翻译剪贴板」按钮 → 点击弹参数表单 → 执行（跑在电脑端）→ 结果经会话消息回流。
**约定**：`handler` 在电脑端执行；长任务不要同步等待，通过发消息/工具调用呈现进展（`POST /m/api/actions/:id/invoke` 立即返回 `accepted`）。
## 3. 自定义推送通道

`pushUrls` 支持 `generic` 格式 —— 任何 HTTP webhook 都能接：

```yaml
pushUrls:
  - name: 我的机器人
    url: https://my-bot.example.com/hook
    format: generic   # POST JSON: { kind, title, detail, sessionId, time }
```

想加一个**正式通道**（像 serverchan/ntfy 那样有专属格式）：
1. 在 `lib/index.js` 的 `pushToChannel` 加一个 `else if (target.format === "xxx")`
2. `docs/03-api.md` 与 README 推送节补说明
## 4. App 定制（dsh-mobile-app）
- **主题**：`lib/theme.dart` —— DeepSeek 设计令牌集中在这一个文件（浅色/深色两套），换色只改这里
- **图标**：覆盖 `assets/icon-1024.png` → `python tools/make_icon.py` → 重新构建
- **页面**：`lib/screens/` 每页一个文件，结构清晰
- **状态/事件**：`lib/store.dart` 全局状态 + SSE 事件桥；`lib/api.dart` 全部 API 调用
- **构建**：见 App README（`flutter analyze` + `flutter build apk --release`）
## 5. 桌面设置页定制（lib/client.js）
- dsh 设置页「连接移动端设备」由 `client.js` 客户端模块提供（React 手写，无构建链）
- 数据来自 `/m/api/qr-config`（仅 loopback）；二维码经 `/m/qr.png?text=...` 生成
- 改文案/布局直接编辑该文件，重启桌面端生效
## 6. 保持兼容的约定
改代码时请守住这些边界（否则可能破坏既有部署）：

- **路由**：`/m` 前缀与 `handleApi` 结构不要动；新端点加在 `handleApi` 内并补文档
- **认证**：新端点默认走统一鉴权；含敏感数据的端点只允许 loopback（参考 `/api/qr-config`）
- **API 兼容**：已发布端点（docs/03-api.md 总表）的响应结构不要破坏性变更；要改就加字段
- **SSE 事件格式**：`summarizeEvent` 输出结构是 App 依赖的契约
- **App 多端并存**：App 与脚本测试共享同一 API，改服务端时都要验证

## 7. 分享你的版本

- **小改动**：直接提 PR 回上游（见 CONTRIBUTING.md）
- **个性化定制**：Fork 后改自己的分支，README 注明基于哪个版本
- **独立插件**：动作区/新端点做成独立 dsh 插件（依赖 `ctx.provide("mobileActions")`），互不冲突
- **展示**：欢迎在 README「衍生项目」区挂你的链接
